# M8 manual test - system tray

Milestone: M8 (§27, §29-§31, §60 "Application" and "Windows", ADR 0016). Run by Max by hand. Fill
in every **Result** line, then send the summary table at the end back.

What M8 adds:

- KeyClean runs from a tray icon; closing the dashboard keeps it running there, with no webview;
- the tray menu: lock, open, settings, quit at idle; the countdown, unlock, show overlay during a
  lock;
- the icon follows the taskbar's light or dark theme, and turns amber while locked;
- the app process no longer registers for Raw Input (invariant 4).

**How long:** step 0 about 13 minutes (automated, two runs), Part A about 15 minutes. Steps marked
_(optional)_ can be skipped.

**Exits you can use in every lock step:** wait for the timer (debug builds stop after 15 s), press
Ctrl+Alt+K, or let a pre-armed PowerShell command kill KeyClean. Nothing in this test needs typing
while something is locked.

**Build and start.** In PowerShell, from `D:\Projects\personal\key-clean`:

```powershell
bun run build; cargo build -p keyclean --features tauri/custom-protocol
.\target\debug\keyclean.exe
```

**Where the tray icon is:** at the right of the taskbar, or in the overflow (the `^` arrow). Drag it
next to the clock first so every step can reach it.

## Preconditions

- [ ] No KeyClean running: `Get-Process keyclean -ErrorAction SilentlyContinue` prints nothing. A
      leftover instance takes over a new start (single instance).
- [ ] Remembered choices at known values: start KeyClean once, pick **1 min** and **Keyboard**
      only, lock, press Ctrl+Alt+K. Debug builds cap the lock at 15 s anyway.

## Step 0 - harness (about 13 minutes)

M8 changes how the harness ends the app (`taskkill /PID` without `/F`, since closing the window no
longer exits) and adds S42-S44.

0. Close any running KeyClean, then run the harness and keep your hands off the keyboard and mouse:

    ```powershell
    cargo build -p keyclean-win --example lock_smoke
    bun run build; cargo build -p keyclean --features tauri/custom-protocol
    cargo run -p keyclean-e2e
    cargo run -p keyclean-e2e -- --overlay-latency --no-dashboard --only S41
    ```

    Expected: every check passes. S41 with `--no-dashboard` reports every lock under 2000 ms.

    **Result:** Pass after fixes (2026-10-12). First full run: 36 passed, 3 failed in 251 s. S31 (cursor moved while the mouse hook blocked every probe, likely a program setting the cursor) passed on its rerun. S12 and S44 found the dashboard close guard unset: Tauri reported the window handle unavailable, so the guard now enumerates the main thread's webview windows, and the two checks wait for it (ADR 0016, first-second gap). Rerun: S11, S12, S31, S43, S44 passed. S41 `--no-dashboard`: first 862 ms, next p50 826 ms, p95 1540 ms, max 1540 ms (all under 2000 ms).

## Part A - debug build (about 15 minutes)

1. **Launch.** Start KeyClean.

    Expected: the dashboard opens, and a tray icon appears: a keycap with a cut-out top and a dot,
    dark on a light taskbar or white on a dark one. Hovering it shows "KeyClean - ready".

    **Result:** Pass (2026-10-12).

2. **Close to tray.** Close the dashboard with its X button.

    Expected: the window closes, the tray icon stays. In Task Manager → Details, `keyclean.exe`
    shows twice (app and engine), and no `msedgewebview2.exe` started by KeyClean is left after
    about 10 s.

    **Result:** Pass (2026-10-12): two `keyclean.exe`, no WebView2 of KeyClean left.

3. **Idle cost.** Wait one minute with the dashboard closed, then look at both `keyclean.exe` in
   Task Manager → Details (add the CPU time column if it's missing).

    Expected: CPU 0 % and CPU time not rising; memory (active private working set) a few MB each.
    Write the two memory numbers here.

    **Result:** CPU 0 % for both (2026-10-12). Memory: pending (the column shown read 0 K).

4. **Open again.** Left-click the tray icon. Close the dashboard, then right-click the icon and
   choose **Open KeyClean**.

    Expected: each time the dashboard opens on the Clean tab with the remembered choices.

    **Result:** Pass (2026-10-12) on a retry with a 1 min lock first. The first try showed 30 s; the remembered duration was 30 s at the time.

5. **Menu at idle.** Right-click the icon.

    Expected, top to bottom: KeyClean, ● Ready (both greyed), Lock keyboard, Lock selected devices,
    Open KeyClean, Settings, Quit, with separators as in ADR 0016.

    **Result:** Pass (2026-10-12): the menu matches.

6. **Settings.** With the dashboard closed, choose **Settings** from the menu. Then switch to the
   Clean tab, and choose **Settings** again with the dashboard open.

    Expected: both times the dashboard shows the Settings tab.

    **Result:** Pass (2026-10-12).

7. **Lock from the tray, dashboard closed.** Close the dashboard. Choose **Lock keyboard**.

    Expected: the overlay appears and the keyboard is locked. Let the timer run out (15 s).
    The overlay disappears and **no window opens**; the icon is back to the outline.

    **Result:** Pass (2026-10-12).

8. **Lock menu.** The overlay covers the monitor under the cursor, taskbar included, so lock with
   the overlay on the **second** monitor: open the dashboard, drag it to the second monitor, choose
   **Keyboard** only, and click Lock there. The mouse stays free, and the main monitor's tray stays
   reachable.

    Expected:
    - the tray icon is amber;
    - right-click: ● Cleaning - 00:12 (counting down; reopen the menu to see it change), Unlock,
      Show overlay, Quit;
    - hovering: "KeyClean - cleaning, 00:12 left";
    - click any window on the main monitor, then choose **Show overlay**: the overlay comes to the
      front and takes focus again;
    - choose **Unlock**: the lock ends at once and the icon is an outline again.

    Also note whether the second monitor's taskbar shows the tray icon (it decides whether the lock
    menu is reachable with one monitor's overlay covering the main taskbar).

    _(No second monitor:)_ lock **Mouse** only from the dashboard instead, press Win+B to focus the
    tray, arrow to the KeyClean icon and press the Menu key (or Shift+F10). Check the same items
    with the keyboard.

    **Result:** Pass (2026-10-12).

9. **Dashboard comes back only if it was open.** Open the dashboard and lock from it (Keyboard,
   any duration). Press Ctrl+Alt+K.

    Expected: the dashboard comes back to the front, as in M7.

    **Result:** Pass (2026-10-12).

10. **A problem opens the dashboard.** Close the dashboard. Pre-arm a kill of the engine process
    only (the app keeps running):

    ```powershell
    Start-Sleep 8; Get-CimInstance Win32_Process -Filter "Name='keyclean.exe'" | Where-Object CommandLine -like '*--engine*' | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
    ```

    Right after pressing Enter, choose **Lock keyboard** from the tray, so the kill lands during
    the 15 s lock.

    Expected: when the engine is killed, the keyboard works at once, the overlay goes, and the
    dashboard opens with "something went wrong" and the engine-restarted notice.

    **Result:** Pass (2026-10-12).

11. **Quit.** Choose **Quit** from the tray.

    Expected: the icon goes away and no `keyclean.exe` is left
    (`Get-Process keyclean -ErrorAction SilentlyContinue` prints nothing).

    **Result:** Pass (2026-10-12).

12. **Second launch.** Start KeyClean, close the dashboard, then start `.\target\debug\keyclean.exe`
    again.

    Expected: the second start exits and the first instance opens its dashboard.

    **Result:** Pass (2026-10-12).

13. **Alt+F4 and the taskbar.** With the dashboard focused (click inside it first), press Alt+F4.
    Open it again, then close it from its taskbar button's right-click menu → Close window.

    Expected: both times the dashboard closes and the tray icon stays (KeyClean doesn't exit).

    **Result:** Pass (2026-10-12), re-run on the build with the dashboard close guard active.

14. **`taskkill` at idle.** With the dashboard open, run `taskkill /IM keyclean.exe` (without `/F`).

    Expected: KeyClean exits; no `keyclean.exe` left within 5 s, and the tray icon goes away.

    **Result:** Pass (2026-10-12), re-run on the build with the dashboard close guard active.

15. **Taskbar theme.** Settings → Personalization → Colors → Choose your mode → Custom; switch
    "Choose your default Windows mode" between Light and Dark.

    Expected: the tray icon switches between the dark and the white outline within a second, with
    no restart.

    **Result:** Pass (2026-10-12).

16. **Display scale.** _(Optional.)_ Settings → System → Display → Scale: change the main
    display from its current value to another (for example 100 % to 150 %), then back.

    Expected: the tray icon stays sharp and the same size as its neighbours each time, with no
    restart.

    **Result:** Skipped.

17. **Engine unavailable.** _(Optional.)_ Kill the engine four times within five minutes, each time
    waiting a second for the restart (the PowerShell command from step 10 without the `Start-Sleep`).

    Expected: after the fourth kill the tray reads "● Engine unavailable - open KeyClean for
    details", and both lock items are greyed out.

    **Result:** Skipped.

18. **Explorer restart.** _(Optional.)_ In Task Manager, restart Windows Explorer.

    Expected: the tray icon comes back by itself.

    **Result:** Skipped.

19. **Forced kill.** _(Optional.)_ `Stop-Process -Name keyclean -Force`.

    Expected: both processes end. The tray icon may stay until the mouse passes over it; that's
    normal Windows behaviour for a killed process.

    **Result:** Skipped.

20. **Release latency.** _(Lock from the tray with no webview open, release build.)_ A release
