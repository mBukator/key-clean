# M5 manual test - mouse and touchpad lock

Milestone: M5 (§22, §23, ADR 0004, ADR 0013). Run by Max by hand. Fill in every **Result** line,
then send the summary table at the end back.

What M5 adds: two checkboxes in the window, **Keyboard** (on by default) and **Mouse and touchpad**
(off by default). With the mouse locked, the cursor, every button, the wheel and the touchpad stop
working until the lock ends. Ctrl+Alt+K, the timer, the hard deadline and killing KeyClean still end
every lock.

**How long:** Part A about 6 minutes, Part B about 10 minutes. Part C is optional.

**Exits you can use in every lock step:** wait for the timer (debug builds stop after 15 s), press
Ctrl+Alt+K, or let a pre-armed PowerShell command kill KeyClean. With the mouse locked, the **Unlock
now** button can't be clicked.

| Build     | How to start (from `D:\Projects\personal\key-clean`) |
| --------- | ---------------------------------------------------- |
| **Debug** | `bun tauri dev` (every lock is capped at 15 s)       |

## Preconditions

- [ ] A PowerShell window open next to KeyClean (for step 6).
- [ ] Notepad open (for step 4).
- [ ] A browser with a long page open (for step 7).

---

## Part A - automated run (about 6 minutes)

1. Close any running KeyClean. In a normal terminal, rebuild, then run the harness and follow its
   prompts:

    ```powershell
    cargo build -p keyclean-win --example lock_smoke
    bun run build; cargo build -p keyclean
    cargo run -p keyclean-e2e
    ```

    Expected: every check passes, including the new mouse checks S26-S32 and S22 (no Raw Input left
    after a mouse lock). Keep your hands off the mouse while it runs: it moves the cursor a little
    and puts it back.

    **Result:**

2. **Touchpad measurement (needs you, about 30 s).** Run:

    ```powershell
    cargo run -p keyclean-e2e -- --mouse-diag --only S33
    ```

    When it says GO, use only the **laptop touchpad** for 15 s: move a finger, tap, click, two-finger
    scroll, three-finger swipe up and down, four-finger swipe left and right, pinch. It ends by
    itself. Copy the numbers it prints into the Result line.

    **Result:**

## Part B - the window (essential)

Start the app: `bun tauri dev`.

3. **Choices.** The **Lock** group shows Keyboard (ticked) and Mouse and touchpad (not ticked).
    - Untick Keyboard: **Start lock** is greyed out. Tick it again.
    - Tick Mouse and touchpad: a hint about Unlock now appears.
    - The Touchpads row in Devices says **Limited** with a note that some gestures may still work.

    **Result:**

4. **Mouse only, ended with Ctrl+Alt+K.** The lock lasts 15 s, so be quick, in this order. Tick
   only **Mouse and touchpad**, pick 30 s, click **Start lock**. Then:
    - The status line says "Mouse and touchpad locked." Move the mouse once: the cursor stays still.
    - The keyboard still works: press Alt+Tab to Notepad and type `abc`. It appears.
    - In Notepad, press **Ctrl+Alt+K**. The mouse works again.
    - Look at Notepad without pressing anything: the menu bar isn't highlighted. (The harness checks
      that K itself never arrives; on a US layout you couldn't see it here anyway.)
    - Back in KeyClean the line under the status says "Last lock ended: you pressed the emergency
      shortcut." If it says "the time ran out", you were too slow: repeat the step.

    **Result:**

5. **Keyboard and mouse, ended by the timer.** Tick both, pick 30 s, click **Start lock**, then take
   your hands off. While locked, try the mouse, touchpad and a few keys: nothing reacts. After about
   15 s the lock ends by itself with "Cleaning complete." Then:
    - Click and drag a window: it works normally (no button stuck down).
    - Type in Notepad: no key stuck (no repeated or shifted letters).

    **Result:**

6. **Kill during a keyboard and mouse lock.** In PowerShell, paste (don't press Enter yet):

    ```powershell
    Start-Sleep 8; Stop-Process -Name keyclean -Force
    ```

    Press Enter, then within 8 s tick both, pick 30 s, and click **Start lock**. Move the mouse: it
    must stop before the 8 s run out (if it never stopped, you were too slow; repeat the step). When
    KeyClean is killed, the mouse and keyboard work again straight away.

    The kill also ends `bun tauri dev`. Start it again for the next step.

    **Result:**

7. **Touchpad during a lock.** The cursor must already be over the browser page when the lock
   starts, because it can't move afterwards. Place KeyClean beside the browser, tick only **Mouse
   and touchpad**, pick 30 s, press **Tab** until **Start lock** is focused, move the cursor over the
   browser page, then press **Enter**. Try each gesture below and note **blocked** or **worked**. If
   15 s isn't enough, start another lock the same way (Ctrl+Alt+K ends one early).

    | Gesture                                 | Blocked / worked |
    | --------------------------------------- | ---------------- |
    | One finger: move the cursor             |                  |
    | Tap to click                            |                  |
    | Physical click (bottom of the pad)      |                  |
    | Two-finger scroll in the browser        |                  |
    | Three-finger swipe up (Task View)       |                  |
    | Four-finger swipe left/right (desktops) |                  |
    | Pinch to zoom in the browser            |                  |

    Also note whether any lock ended early with "Windows stopped KeyClean's mouse lock early".

    **Result:**

## Part C - optional

8. _(Optional)_ **Unlock now with the keyboard in a mouse-only lock.** Tick only Mouse and
   touchpad, click **Start lock**, then press Tab until **Unlock now** is focused and press Enter.
   Expected: the lock ends ("it was cancelled"). Record whether Tab reaches the button.

    **Result:**

9. _(Optional)_ **USB device unplugged and plugged in during a mouse lock.** Tick both, start a lock,
   unplug the Logitech receiver, then plug it back in. It is a keyboard and a mouse at once, and the
   window shows only the newest notice, so either kind may show: "Keyboard disconnected." or "Mouse
   or touchpad disconnected.", then "A keyboard was connected. It is locked too." or "A mouse or
   touchpad was connected. It is locked too." Expected: a notice appears each time, the lock
   continues, and the replugged device is locked.

    **Result:**

10. _(Optional)_ **Keyboard plugged in during a mouse-only lock.** Tick only Mouse and touchpad,
    start a lock, plug in the HyperX keyboard. It types normally. Expected notice: "A keyboard was
    connected." (without "It is locked too"), or "A mouse or touchpad was connected. It is locked
    too." for its mouse interface, whichever Windows reports last.

    **Result:**

11. _(Optional)_ **Administrator window.** Open Task Manager as administrator and place KeyClean
    beside it. Tick only Mouse and touchpad, press Tab until **Start lock** is focused, move the
    cursor over Task Manager, press Enter. Try clicking and scrolling over Task Manager. Record
    blocked or worked, and any notice.

    **Result:**

12. _(Optional)_ **Logitech digitizer.** If the Logitech receiver's device has a touch surface, repeat
    step 7's first four rows with it.

    **Result:**
