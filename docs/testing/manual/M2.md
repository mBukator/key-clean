# M2 manual test - timer and automatic unlock

Milestone: M2 (§11, §15, §16, §19, §60 "Timer"). Run by Max, never by Claude. Fill in every
**Result** cell, then send the summary table at the end back to Claude.

What M2 adds to the M1 shell: four duration presets (30 seconds, 1 minute, 2 minutes, 5 minutes; 2
minutes selected by default), a live countdown that comes from the engine, an **Unlock now** button,
and a "Cleaning complete" message when the timer ends the lock.

There are two builds:

| Build       | How to start (from `D:\Projects\personal\key-clean`)                               | Lock length                                        |
| ----------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| **Debug**   | `bun tauri dev` (leave the terminal open; it prints session events)                | Every preset is capped at 15 s, hard deadline 20 s |
| **Release** | `bun tauri build` once, then run `.\target\release\keyclean.exe` (Part C explains) | The real preset length, hard deadline + 10 s       |

The release build has no console, so its outcomes are read from the window only.

## The no-keyboard rule

While a lock is active you never need the keyboard to get out. Every step ends by itself (the timer),
by the mouse (**Unlock now**; KeyClean M2 never locks the mouse), or by a PowerShell command you start
**before** locking. Ctrl+Alt+K always works too.

## Preconditions

- [ ] Save your work in every open app.
- [ ] Mouse or touchpad connected and working.
- [ ] **Notepad** open (the "did a key get through?" detector) and the **On-Screen Keyboard** open
      (`osk`), only to look at.
- [ ] A stopwatch you can start without the keyboard (phone).

"Stuck-key check" means, as in M1: no modifier key is lit on the On-Screen Keyboard, and typing `abc` in
Notepad gives lowercase `abc`.

## Part A - automated run (do this first)

The engine changed (countdown timer), so run the whole harness, not only the new checks. It takes about
2.5 minutes and locks your keyboard several times: hands off the keyboard until it prints the results.

1. Close any running KeyClean and pause keyboard tools (AutoHotkey, PowerToys Keyboard Manager).
2. Build both targets:

    ```powershell
    cargo build -p keyclean-win --example lock_smoke
    bun run build; cargo build -p keyclean
    ```

3. Run it, then click into an empty Notepad window during the 5 s countdown:

    ```powershell
    cargo run -p keyclean-e2e
    ```

    Rebuild the app every time: `cargo run -p keyclean-e2e` rebuilds only the harness. If `keyclean.exe`
    is older than its sources, the app checks (S10-S12, S14, S15) are skipped with a "rebuild it" note.

4. Send Claude the printed table (also saved as `target\debug\e2e-report.md`).

| Harness check | Covers | What it proves                                                                                                                                                                                  |
| ------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1-S14        | M1.md  | Nothing in M1 regressed                                                                                                                                                                         |
| S15           | M2 1   | A 5 s lock run by the real engine process shows 5, 4, 3, 2, 1 once each, each within 150 ms of its second boundary, ends with `Timeout` on time, and sends no more countdown statuses once idle |
| S16           | M2 2   | With the session timer switched off (test builds only), the hard deadline alone ends a 3 s lock after about 13 s with `HardDeadline`                                                            |

S16 is the only check of "safety timeout works" with a broken session timer: a normal build can't switch
its timer off, so there is no manual step for it.

## Part C - release build, real durations (about 10 minutes)

These locks last as long as the preset says, up to 5 minutes. Ctrl+Alt+K ends them at any time, and the
hard deadline (preset + 10 s) ends them even if the timer fails.

Build once (this runs `bun run build` itself; bundling is off, so it only produces the exe):

```powershell
bun tauri build
Get-ChildItem .\target\release\*.exe
```

Close `bun tauri dev` first (single instance), then start the exe that the second command lists (expected
`keyclean.exe`). The window has **no** DEV CAP badge.

### Step 6 - 30 seconds against a stopwatch

1. Select **30 seconds**. Start the stopwatch and click **Lock keyboard** at the same moment.
2. Click into Notepad. When the stopwatch shows 10 s, read the countdown.

**Expected:** the countdown starts at **00:30** and shows 00:20 (±1) at the 10 s mark. The lock ends when
the stopwatch shows 30 s ±1 s, with "Cleaning complete". Stuck-key check passes.

|                   |                      |        |

### Step 7 - 5 minutes in the background against a stopwatch

This checks that the countdown stays accurate while KeyClean is not the active window.

1. Select **5 minutes**. Start the stopwatch and click **Lock keyboard** at the same moment.
2. Click into Notepad and leave KeyClean in the background (don't minimize it, so you can glance at it).
3. Read the countdown at stopwatch 1:00, 2:30 and 4:00.

**Expected:** the countdown starts at **05:00** and reads 04:00, 02:30 and 01:00 (each ±1 s) at those
marks. The lock ends when the stopwatch shows 5:00 ±1 s, with "Cleaning complete". Stuck-key check
passes.

### Step 10 - Killing the release app mid-lock

1. In a PowerShell window, type and start this **before** locking:

    ```powershell
    Start-Sleep 20; Stop-Process -Name keyclean -Force
    ```

2. Within the 20 s, select **2 minutes** in KeyClean and click **Lock keyboard**, then click into
   Notepad.

**Expected:** about 20 s after you started the command, the KeyClean window disappears and typing in
Notepad works again. Task Manager shows no `keyclean.exe` left. Stuck-key check passes.

**Expected:** after the lock ends, both show 0% CPU (no countdown ticks at idle).
