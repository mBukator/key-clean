# M3 manual test - safety hardening

Milestone: M3 (§26, §47, §53, §60 "Safety"). Run by Max, never by Claude. Fill in every **Result**
cell, then send the summary table at the end back to Claude.

What M3 adds:

- **Lost-hook check.** If Windows drops KeyClean's keyboard hook mid-lock, the lock ends at once
  with "Windows stopped KeyClean's keyboard lock early." (ADR 0010).
- **Admin-window warning.** If an administrator window has focus and typing reaches it, the window
  says "Typing reaches administrator windows during a lock." and the lock stays on everywhere else.
- **Keyboard notices.** Connecting or disconnecting a keyboard during a lock shows a notice, and the
  keyboard list refreshes.
- **Engine restart.** If the engine process dies, the app starts a new one, idle, at most 3 times in
  5 minutes (ADR 0011).
- **Clean exit on `taskkill`.** `taskkill` without `/F` now closes the app cleanly instead of hanging
  its window.

Most of M3 is checking behaviour that already exists, through real system events: shutdown,
restart, sign-out, switch user, sleep, clock changes, and plugging devices in and out.

| Build       | How to start (from `D:\Projects\personal\key-clean`)                      | Lock length                          |
| ----------- | ------------------------------------------------------------------------- | ------------------------------------ |
| **Debug**   | `bun tauri dev` (leave the terminal open; it prints session events)       | Capped at 15 s, hard deadline 20 s   |
| **Release** | `bun tauri build` once, then `.\target\release\keyclean.exe` (no console) | The real preset, hard deadline +10 s |

## The no-keyboard rule

You never need the keyboard to get out of a lock. Every step ends by itself (the timer), by the mouse
(**Unlock now**; M3 never locks the mouse), or by a PowerShell command you start **before** locking.
Ctrl+Alt+K always works too.

## Preconditions

- [ ] Save your work in every open app. Steps 1-3 shut down, restart and sign out.
- [ ] Mouse or touchpad connected and working.
- [ ] **Notepad** open (the "did a key get through?" detector) and the **On-Screen Keyboard** open
      (`osk`), only to look at.
- [ ] For step 6: a USB (or Bluetooth) keyboard you can unplug or switch off.
- [ ] For step 5: an **administrator** PowerShell (right-click Start → Terminal (Admin)).
- [ ] A stopwatch you can start without the keyboard (phone).

"Stuck-key check" means, as before: no modifier key is lit on the On-Screen Keyboard, and typing `abc`
in Notepad gives lowercase `abc`.

    cargo build -p keyclean-win --example lock_smoke

## Part C - devices, admin windows and crashes (debug build)

Start `bun tauri dev` and leave the terminal visible. Each lock lasts 15 s (DEV CAP).

### Step 6 - Unplug and replug a keyboard during a lock

1. Click **Lock keyboard**. Unplug the external keyboard (or switch it off). Wait 2 s, then plug it
   back in (switch it on).
2. Type on both keyboards into Notepad until the lock ends by its timer.

**Expected:**

- On unplug, the window says "Keyboard disconnected." and the keyboard list loses that keyboard. The
  terminal prints `[keyclean] device: Removed`.
- On replug, it says "A keyboard was connected. It is locked too." and the keyboard is listed again.
  The terminal prints `device: Arrived`.
- Nothing typed on either keyboard appears in Notepad, and nothing crashes. After the timer both
  keyboards work. Stuck-key check passes.

### Step 8 - Engine process killed mid-lock

In a normal PowerShell, pre-arm a kill of the engine process only (press Enter now):

```powershell
Start-Sleep 8; Get-CimInstance Win32_Process -Filter "Name='keyclean.exe'" | Where-Object CommandLine -like '*--engine*' | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

Within 5 s, click **Lock keyboard** and click into Notepad.

**Expected:** about 8 s after Enter, typing works again at once. The window says "KeyClean's lock
engine stopped and was restarted. Nothing is locked." and shows **Ready**. The terminal prints
`[keyclean] engine restarted`. Then click **Lock keyboard** again: the new lock works, and ends by the
timer. Stuck-key check passes.

### Step 11 - Xbox Game Bar (Win+G) during a lock

1. Click **Lock keyboard** and click into Notepad. Press the physical **Win+G**.
2. If the Game Bar opens, type a few letters, then click into Notepad and type a few more.
3. Let the lock end by its timer. Close the Game Bar (click outside it). Stuck-key check.

**Expected:**

- The Game Bar opens: Win+G is documented as unblockable.
- Typing does nothing, either in the overlay or in Notepad: the hook still blocks keys.
- The lock ends by the timer (`session ended: Timeout`).
- No "Windows stopped KeyClean's keyboard lock early" message appears. While the overlay is open, the
