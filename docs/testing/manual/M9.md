# M9 manual test - global shortcut

Milestone: M9 (§28, §32 "Shortcuts", invariant 8, ADR 0005 amendment, ADR 0017). Run by Max by
hand. Fill in every **Result** line, then send the summary table at the end back.

What M9 adds:

- a start shortcut (default Ctrl+Shift+K) that locks from any app, through the overlay, with the
  remembered duration;
- Settings → Shortcuts: change it ("press the new shortcut"), turn it off, choose what it locks,
  try again when another app holds it;
- the shortcut on the Clean screen and next to its tray item.

**How long:** step 0 about 11 minutes (automated), steps 1-11 about 20 minutes. Steps marked
_(optional)_ can be skipped.

**Exits you can use in every lock step:** wait for the timer (debug builds stop after 15 s), press
Ctrl+Alt+K, or let a pre-armed PowerShell command kill KeyClean. Nothing in this test needs typing
while something is locked; typing during a lock only checks that it is blocked.

**Stuck-key check** (after a lock ends): click into Notepad and type `abc`. Expected: `abc` in lower
case (Shift isn't stuck), and no menu or shortcut fires (Ctrl and Alt aren't stuck).

**Build and start.** In PowerShell, from `D:\Projects\personal\key-clean`:

```powershell
bun run build; cargo build -p keyclean --features tauri/custom-protocol
.\target\debug\keyclean.exe
```

## Preconditions

- [ ] No KeyClean running: `Get-Process keyclean -ErrorAction SilentlyContinue` prints nothing.
- [ ] Remembered choices: start KeyClean, pick **1 min** with **Keyboard** and **Mouse** both on,
      click Lock, then press Ctrl+Alt+K. The shortcut's "Lock selected devices" now means both.
- [ ] Notepad open on the monitor you'll use.

## Steps (debug build)

1. **Lock from another app.** Close the dashboard (X), click into Notepad, press **Ctrl+Shift+K**
   and let go.

    Expected: the overlay appears on the monitor under the cursor within about 2 s and the keyboard
    is locked (typing in Notepad does nothing). The mouse is locked too (see Preconditions). After
    15 s the overlay closes, no window opens, and the stuck-key check passes.

    **Result:**

2. **Where it shows.** Open KeyClean from the tray. Look at the Clean screen, then Settings, then
   right-click the tray icon.

    Expected: the Clean screen's dark panel shows "Start shortcut: Ctrl + Shift + K" under the
    emergency shortcut. Settings → Shortcuts shows Ctrl + Shift + K, "Lock selected devices"
    selected, and Emergency unlock Ctrl + Alt + K (read-only). The tray menu shows "Ctrl+Shift+K"
    right-aligned next to **Lock selected devices**.

    **Result:**

3. **What it locks.** In Settings choose **Lock keyboard**. Click into Notepad, press
   Ctrl+Shift+K.

    Expected: only the keyboard locks; the mouse still moves. The tray menu (before the lock) moved
    the shortcut next to **Lock keyboard**. After the lock, set it back to **Lock selected
    devices**.

    **Result:**

4. **Change it.** Settings → **Change**, then press **Alt+Shift+1**.

    Expected: "Saved." and the shortcut reads Alt + Shift + 1 (Settings, Clean screen, tray). In
    Notepad, Ctrl+Shift+K now does nothing; Alt+Shift+1 locks.

    **Result:**

5. **Refused shortcuts.** Settings → **Change**, then press, one after another: **Ctrl+Alt+K**,
   **Ctrl+C**, **Win+Shift+K** _(Windows may act on this one itself)_. Then press **Esc**.

    Expected: each shows a plain message (emergency unlock; hold Shift and Ctrl or Alt; Windows
    key) and the field keeps waiting. Esc ends the pick, and Alt + Shift + 1 still locks.

    **Result:**

6. **Picking pauses the shortcut.** Settings → **Change**, then press the current **Alt+Shift+1**.
   Then **Change** again and close the dashboard with its X while it waits.

    Expected: the first press saves Alt + Shift + 1 again and starts no lock. After the dashboard
    closes, Alt+Shift+1 in Notepad locks (the shortcut came back).

    **Result:**

7. **Off and on.** Settings → **Turn off**. Press Alt+Shift+1 in Notepad. Then **Choose a
   shortcut** and press **Ctrl+Shift+K**.

    Expected: off: the Clean screen says "Start shortcut: off", the tray shows no shortcut, and the
    press does nothing. After choosing, Ctrl+Shift+K works again.

    **Result:**

8. **Taken by another app.** Quit KeyClean (tray → Quit). In a **new** PowerShell window, run
   this (it holds Ctrl+Shift+K for 60 s, prints `True`, then releases it and prints `True` again):

    ```powershell
    Add-Type -Namespace W -Name H -MemberDefinition '[DllImport("user32.dll")] public static extern bool RegisterHotKey(IntPtr h, int id, uint mods, uint vk); [DllImport("user32.dll")] public static extern bool UnregisterHotKey(IntPtr h, int id);'; [W.H]::RegisterHotKey([IntPtr]::Zero, 1, 0x4006, 0x4B); Start-Sleep 60; [W.H]::UnregisterHotKey([IntPtr]::Zero, 1)
    ```

    Within the 60 s, start KeyClean and open Settings. When the PowerShell prompt is back, close
    that PowerShell window (in case the release didn't take), then click **Try again**. To repeat
    the step, use a new PowerShell window: `Add-Type` fails a second time in the same one.

    Expected: KeyClean starts normally. Settings shows "KeyClean couldn't set up the start
    shortcut. Another app may already be using it." with technical details and **Try again**; the
    Clean screen says the shortcut isn't working; the tray shows no shortcut. After Try again:
    Ctrl + Shift + K is active and locks.

    **Result:**

9. **Held through the lock start.** Click into Notepad. Press **Ctrl+Shift+K** and keep holding
   all three keys until the overlay is up (about 2 s), then let go.

    Expected: the lock runs its 15 s; after it, the stuck-key check passes.

    **Result:**

10. **A second press during a mouse-only lock.** Open KeyClean, set **Mouse** only on the Clean
    screen, lock, press Ctrl+Alt+K (this makes "selected devices" the mouse only). Close the
    dashboard. Press Ctrl+Shift+K, then once the overlay is up press **Ctrl+Shift+K** again.

    Expected: the second press changes nothing: same overlay, countdown keeps going, it ends after
    15 s, and no window opens. Afterwards set Keyboard and Mouse again for later steps.

    **Result:**

11. **Administrator window (measurement for ADR 0005).** In Settings choose **Lock keyboard**, so
    the mouse stays free, and close the dashboard. Right-click Start → **Terminal (Admin)**, accept
    the prompt, and move that window to your **second monitor**. Click into it, then move the
    cursor back to the **first monitor** (the overlay goes on the monitor under the cursor). Press
    **Ctrl+Shift+K**.

    Record:

    - (a) Did a lock start (overlay shown on the first monitor)?
    - (b) Which window had the focus once the overlay was up: the overlay, or the admin terminal
      (its title bar active)?
    - (c) Click into the admin terminal with the mouse and type a few letters. Did they appear?
    - (d) How did the lock end, and does the dashboard (open it afterwards) show "Typing reaches
      administrator windows during a lock."?

    Then repeat with **Task Manager** on the second monitor instead _(optional)_. Afterwards set the
    shortcut back to **Lock selected devices**.

    **Result:**

12. _(optional)_ **Idle cost.** With the dashboard closed for a minute, look at both
    `keyclean.exe` in Task Manager → Details.

    Expected: CPU 0 %, CPU time not rising.

    **Result:**
