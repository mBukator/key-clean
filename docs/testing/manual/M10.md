# M10 manual test - start with Windows and notifications

Milestone: M10 (§29, §30, §31, §32 "General", ADR 0018). Run by Max by hand. Fill in every
**Result** line, then send the summary table at the end back.

What M10 adds:

- Settings → General: **Start with Windows** (release builds only), **Start minimized**, **Show
  notifications**;
- a start at sign-in stays in the tray with no window;
- Windows notifications when a lock ends with no dashboard open, and for problems at sign-in.

**How long:** step 0 about 6 minutes (automated); steps 1-6 (debug build) about 10 minutes; steps
7-12 (release build) about 15 minutes, including two sign-outs (about 2 minutes each). Steps
marked _(optional)_ can be skipped.

**Exits you can use in every lock step:** wait for the timer (debug builds stop after 15 s), press
Ctrl+Alt+K, or let a pre-armed PowerShell command kill KeyClean
(`Start-Sleep 8; Stop-Process -Name keyclean -Force`). No step needs typing while something is
locked. The release steps don't lock.

**Toasts before M11:** from `target\debug` and `target\release`, Windows shows KeyClean's toasts as
**Windows PowerShell** (with PowerShell's icon). That is expected until the installer exists. If
toasts don't appear at all, check Settings → System → Notifications: notifications on, and
"Windows PowerShell" allowed.

**Build (debug).** In PowerShell, from `D:\Projects\personal\key-clean`:

```powershell
bun run build; cargo build -p keyclean --features tauri/custom-protocol
```

## Preconditions

- [ ] No KeyClean running: `Get-Process keyclean -ErrorAction SilentlyContinue` prints nothing.
- [ ] No startup entry yet:
      `Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run -Name KeyClean -ErrorAction SilentlyContinue`
      prints nothing.
- [ ] Notepad open.

## Step 0 - harness (about 6 minutes)

M10 adds S49-S51. S51 shows one "Cleaning complete. Keyboard unlocked." toast as Windows
PowerShell; that is expected.

0. Close any running KeyClean, then run the harness and keep your hands off the keyboard and mouse:

    ```powershell
    cargo build -p keyclean-win --example lock_smoke
    bun run build; cargo build -p keyclean --features tauri/custom-protocol
    cargo run -p keyclean-e2e
    ```

    Expected: every check passes. S42 and S23 still log "close guard: 4 helper windows".

    **Result:**

## Steps (debug build)

Start KeyClean: `.\target\debug\keyclean.exe`

1. **Settings → General.** Open the Settings tab.

    Expected: a **General** section at the top with three switches. **Start with Windows** is off
    and greyed out, with "Only release builds of KeyClean can start with Windows." **Start
    minimized** and **Show notifications** are on (unless you changed them before).

    **Result:**

2. **Toast after a lock with no window open.** Close the dashboard (X). Click into Notepad and
   press **Ctrl+Shift+K** (the start shortcut). Let the timer end the lock (15 s), then type `abc`
   right away, while the toast is still on screen.

    Expected: no toast while the overlay is up. About a second after the overlay goes, a toast
    "Cleaning complete. Keyboard unlocked." (or "… Keyboard and mouse unlocked." if your remembered
    choice includes the mouse). `abc` appears in Notepad in lower case: the toast didn't take the
    focus, and no key is stuck.

    **Result:**

3. **No toast with the dashboard open.** Open KeyClean, click **Lock**, let the timer end it.

    Expected: no toast; the dashboard shows the result as before.

    **Result:**

4. **No toast after Ctrl+Alt+K.** Close the dashboard. Tray → **Lock keyboard**, then press
   **Ctrl+Alt+K** once the overlay is up.

    Expected: the lock ends; no toast.

    **Result:**

5. **Notifications off.** Open Settings → General, turn **Show notifications** off. Close the
   dashboard, tray → **Lock keyboard**, let the timer end it. Then turn **Show notifications** back
   on.

    Expected: no toast. The switch stays as you set it after closing and reopening KeyClean.

    **Result:**

6. **A start at sign-in, simulated.** Quit KeyClean (tray → Quit). Then:

    ```powershell
    .\target\debug\keyclean.exe --autostart
    ```

    Wait 5 s, then run the same command again. Then run `.\target\debug\keyclean.exe` (no
    argument).

    Expected: the first command starts KeyClean in the tray with no window. The second exits and
    opens nothing. The plain launch opens the dashboard. Quit KeyClean from the tray afterwards.

    **Result:**

## Steps (release build)

Release builds lock for the real length, but these steps don't lock (except step 8's optional
check). Build it and check nothing else is running:

```powershell
bun tauri build
Get-Process keyclean -ErrorAction SilentlyContinue
```

7. **Turn it on.** Start `.\target\release\keyclean.exe`. Settings → General → turn **Start with
   Windows** on. Then read the registry:

    ```powershell
    Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run -Name KeyClean
    Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Run -Name KeyClean -ErrorAction SilentlyContinue
    ```

    Expected: the switch is on. The first command shows
    `"D:\Projects\personal\key-clean\target\release\keyclean.exe" --autostart` (with the quotes).
    The second prints nothing (no entry for every user).

    **Result:**

8. **Sign out and in (about 2 minutes).** Leave **Start minimized** on. Quit KeyClean, sign out,
   sign back in. Note roughly how long after the desktop appears the KeyClean tray icon shows up.
   Then hover it, and open its menu.

    Expected: the tray icon appears (Windows may take up to a minute or so); no KeyClean window
    opens. The tooltip reads "KeyClean - ready" (not "engine unavailable"); the menu shows the
    shortcut next to its item. _(Optional:_ click into Notepad and press **Ctrl+Shift+K**, then
    **Ctrl+Alt+K** as soon as the overlay is up: it locks, then unlocks; no toast after the
    chord._)_

    **Result:** (icon after about … s)

9. **Idle cost.** Don't open the dashboard. Two minutes after sign-in, run this, wait 60 s, and run
   it again:

    ```powershell
    Get-Process keyclean | Select-Object Id, @{n='CPU s';e={$_.CPU}}, @{n='WS MB';e={[math]::Round($_.WorkingSet64/1MB,1)}}, @{n='Private MB';e={[math]::Round($_.PrivateMemorySize64/1MB,1)}}
    ```

    Expected: two `keyclean.exe` processes (the app and its engine). CPU seconds don't change
    between the two readings (or by less than 0.1). Record both memory columns for each process.

    **Result:**

10. **Start minimized off (about 2 minutes).** Open KeyClean from the tray, Settings → General →
    turn **Start minimized** off. Sign out and back in.

    Expected: at sign-in, KeyClean's dashboard opens by itself. Afterwards turn **Start
    minimized** back on.

    **Result:**

11. **Turned off in Task Manager.** Open Task Manager → **Startup apps**, right click **KeyClean**
    → **Disable**. In KeyClean, switch to the Clean tab and back to Settings.

    Expected: the Start with Windows switch stays on, with "Turned off in Task Manager → Startup
    apps. Turn it back on there."

    Then, still disabled in Task Manager: turn the switch **off** in KeyClean, read Task Manager's
    record, and turn the switch **on** again:

    ```powershell
    Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run -Name KeyClean -ErrorAction SilentlyContinue
    ```

    Record whether the command prints a `KeyClean` value (Windows kept Task Manager's record after
    the entry was removed) or nothing. If it printed one, the switch comes back on with the same
    note; if not, with no note.

    Finally **Enable** KeyClean in Task Manager and switch tabs again: the switch is on, with no
    note.

    **Result:**

12. **Turn it off.** Settings → General → turn **Start with Windows** off. Run the first command
    from step 7 again.

    Expected: the switch is off; the command prints an error that the property doesn't exist (no
    entry left).

    **Result:**

## Optional steps

13. _(optional)_ **Another copy.** Turn **Start with Windows** on in the release build (step 7),
    quit it, start the debug build and open Settings → General.

    Expected: the switch is off and greyed, with only the release-build note. Run the first
    command from step 7: it still shows the release exe (the debug build changed nothing). Turn it
    off again in the release build afterwards (step 12).

    **Result:**

14. _(optional)_ **Shortcut taken at sign-in, simulated.** Quit KeyClean. In a new PowerShell
    window, hold Ctrl+Shift+K for 60 s (as in M9.md step 8):

    ```powershell
    Add-Type -Namespace W -Name H -MemberDefinition '[DllImport("user32.dll")] public static extern bool RegisterHotKey(IntPtr h, int id, uint mods, uint vk); [DllImport("user32.dll")] public static extern bool UnregisterHotKey(IntPtr h, int id);'; [W.H]::RegisterHotKey([IntPtr]::Zero, 1, 0x4006, 0x4B); Start-Sleep 60; [W.H]::UnregisterHotKey([IntPtr]::Zero, 1)
    ```

    Within the 60 s, in another window run `.\target\debug\keyclean.exe --autostart`.

    Expected: KeyClean starts in the tray, and a toast says "KeyClean couldn't set up the start
    shortcut. Another app may already be using it." Quit KeyClean afterwards.

    **Result:**

15. _(optional)_ **Do Not Disturb.** Turn on Do Not Disturb (notification centre), then repeat
    step 2. Turn it off afterwards.

    Expected: no banner; the toast is listed in the notification centre.

    **Result:**
