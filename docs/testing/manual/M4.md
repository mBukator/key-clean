# M4 manual test - device detection

Milestone: M4 (§22-§24, §26, ADR 0004, ADR 0012). Run by Max, never by Claude. Fill in every
**Result** cell, then send the summary table at the end back to Claude.

What M4 adds: a **Devices** list in the window that shows every connected keyboard, mouse, touchpad,
touchscreen and pen with its friendly name and a **Supported / Limited / Unsupported** label, and
that updates by itself when a device is plugged in or unplugged. Nothing new is locked: every
keyboard is locked as before, mice and touchpads still are not (M5).

M4 never locks anything in this test, so you can use the keyboard freely. Locking is only covered
by the harness run in Part A.

| Build     | How to start (from `D:\Projects\personal\key-clean`)                                |
| --------- | ----------------------------------------------------------------------------------- |
| **Debug** | `bun tauri dev` (leave the terminal open; it prints `[keyclean] devices: N listed`) |

## Preconditions

- [ ] A USB (or Bluetooth) keyboard **or** mouse you can unplug and plug back in. Both is better.
- [ ] Device Manager open (`devmgmt.msc`), with **Keyboards**, **Mice and other pointing devices**
      and **Human Interface Devices** expanded, for comparing names.
- [ ] If you have a touchscreen or pen, note it; if not, steps 9 and 10 are optional.

---

## Part A - automated run (about 4 minutes)

1. Close any running KeyClean. Run from a normal terminal, then follow the harness's own prompts:

    ```powershell
    cargo build -p keyclean-win --example lock_smoke
    bun run build; cargo build -p keyclean
    cargo run -p keyclean-e2e
    ```

    Expected: every check passes. M4 changed two of them:

    - **S1 (keyboards listed):** passes with a line like `2 keyboard(s) among 5 device(s) listed`.
    - **S22 (no Raw Input at idle):** passes with the device watch running. This is the invariant 4
      check: watching for devices must not register for input.

    **Result:** PASS, 2026-10-04: 22 passed, 0 failed in 100 s. S1: `4 keyboard(s) among 8 device(s)
 listed`. S22: no Raw Input registration, also with the device watch running.

## Part B - the device list

Start the app: `bun tauri dev`.

2. **First list.** The Devices section shows your devices in groups: Keyboards, Mice, Touchpads and,
   if you have any, Other input devices. Each row has a name and a label. Compare with Device
   Manager.
    - Every keyboard and mouse you know of is listed, with a name that makes sense (a generic name
      such as "HID Keyboard Device" is fine, it is what Windows reports).
    - Keyboards and mice say **Supported**.
    - The line under the list says: "Every connected keyboard is locked during a session. Mice and
      touchpads aren't locked yet."

    **Result:** PASS, 2026-10-04 (after the folding fix): Keyboards: HyperX Alloy Origins, Standard PS/2 Keyboard, USB Receiver. Mice: HyperX Alloy Origins, USB Receiver. Touchpads: ASUS Precision Touchpad (Limited), USB Receiver (Limited). Footnote text as expected.

3. **Plug in** the USB device. Within about a second the list gains it, in the right group, with a
   name (not "Unnamed device").

    **Result:** Not reported on its own; covered by steps 5 and 6, which replug the device and followed the list.

4. **Unplug** it. Within about a second it disappears from the list. No error appears.

    **Result:** PASS: unplugging the USB keyboard removed its rows (before the folding fix: 3 rows gone, afterwards 1 keyboard + 1 mouse row).

5. **Repeat** steps 3-4 three times quickly (plug, unplug, plug, unplug, plug). The final list matches
   what is plugged in. No duplicate rows, no error.

    **Result:** PASS, 2026-10-04.

6. **Another port or a Bluetooth device.** Plug the device into a different USB port, or switch a
   Bluetooth keyboard or mouse off and on. The list follows each change.

    **Result:** PASS, 2026-10-04.

7. **A device with several interfaces.** Your HyperX keyboard and Logitech receiver are the test:
   each USB device should make **one row per kind**, named by product: "HyperX Alloy Origins" under
   Keyboards (once, not twice) and under Mice (it has a mouse interface), and "USB Receiver" under
   Keyboards, Mice and Touchpads (the receiver reports a touchpad collection). The built-in
   keyboard and touchpad keep their own names. Try a Bluetooth keyboard or mouse if you have one:
   the name should be the product, not a generic one.

    **Result:** PASS, 2026-10-04: one row per kind per USB device, named by product (see step 2). The "USB Receiver" touchpad row is the receiver's digitizer collection.

8. **Sleep.** Unplug the USB device, put the PC to sleep, plug it back in while asleep (or the other
   way round), wake it. Does the list match what is plugged in after wake?

    **Result:** PASS, 2026-10-04: the list matched after wake.

9. **Touchpad.** On a laptop: the touchpad is listed under **Touchpads** with **Limited** and the
   sentence "Windows treats a precision touchpad like a mouse...". If the laptop's touchpad shows
   under **Mice** instead, say so: it is a non-precision touchpad (Windows treats it as a mouse).
   There is no extra "mouse" row for the same touchpad. No laptop: write "no touchpad".

    **Result:** PASS: "ASUS Precision Touchpad" under Touchpads, Limited, with the note; no extra mouse row for it.

10. **Touchscreen and pen.** If you have either, it appears under **Other input devices** with
    **Unsupported** and "KeyClean can't lock touchscreens." (or pens). None: write "none".

    **Result:** None (no touchscreen or pen).

11. **Window size.** Make the window narrow (about 400 px) and zoom the text to 200%. Names wrap and
    nothing is cut off or hidden.

    **Result:** PASS, 2026-10-04.

12. **Idle cost.** With the window open and nothing changing, Task Manager shows `keyclean.exe` at
    0% CPU. After unplugging and plugging once more it goes back to 0%.

    **Result:** PASS, 2026-10-04: 0% CPU while idle.

13. **Lock still works.** Press **Lock keyboard** (debug build: 15 s at most). The keyboard locks,
    and **Unlock now** with the mouse (or the timer, or Ctrl+Alt+K) ends it. While locked, unplug and
    replug the USB keyboard: the notice appears as in M3 and the list stays right afterwards.

    **Result:** NOT RUN (2026-10-04): skipped by Max, who accepted M4 without it. The lock and the notice for a keyboard unplugged during a lock were verified in M3 and M4 changes neither.

14. **Close and reopen.** Close the app, start it again. The list is complete straight away (no empty
    list that fills in later).

    **Result:** PASS, 2026-10-04.
